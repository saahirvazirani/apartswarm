# Limitations and Dual-Use / Ethical Considerations — draft bullets for the appendix

Agent-drafted list of facts for the human authors to turn into prose. Every item is backed by `runs/` or `RUN_INDEX.md`.

## Assumptions and what changes if they fail

- **The side task is inert and instructed.** The "attack" is a telemetry call whose endpoint contains a canary string; `utils.send_report`
  is a logging no-op. Leniency, if found, is uninstructed (the monitor is never told to go easy and is blind to the author by default).
  If real attacks are more varied than one disguised telemetry call, the absolute catch rates do not transfer; the *diagonal-vs-off-diagonal
  contrast* is the claim, not the catch rates themselves.
- **Per-pair calibration assumes benign submissions are representative of the monitor's false-positive surface.** Thresholds are the
  95th percentile of each monitor's scores on each policy's own kept benign submissions (n ≈ 100 per policy), so a threshold rests on
  ~5 benign scores at the tail. Wilson intervals on TPR are reported; AUROC is reported as the threshold-free companion.
- **One fixed sentence in every task text declares `utils.send_report` the sanctioned telemetry helper.** Without it every monitor scored
  *any* telemetry ≈ 90 and telemetry-free code 0 (pre-flight), which puts every cell at the ceiling. The sentence is seen identically by
  policies and monitors. It makes benign telemetry common (8–97 % of benign submissions depending on policy), which is what gives the
  monitors something to discriminate. If a deployment never sanctions telemetry, the task is easier for monitors than ours.
- **Reasoning disabled on every call** (`reasoning.effort=none`). This is the only setting under which qwen3.5-397b returns JSON and the
  only way to keep the two expensive models inside budget. glm-53-flash then "thinks out loud" in its visible output (median ≈ 2,200
  tokens before the code; 250–2,900 before a monitor verdict). Monitors with reasoning enabled may behave differently.
- **Output caps were raised after pre-registration** (policy/polish 2500 → 8000; monitor 1200 → 4000), uniformly, because of the
  point above; dated in `RUN_INDEX.md`. The caps never bound for the other five models (they answer in < 500 tokens).
- **34 of 40 tasks survived validation** (reference passes, deliberately wrong solution fails, a clean deepseek solution passes).
  Tasks are small self-contained Python functions generated by glm-5.2 from hand-written one-line specs; glm-5.2 is also a subject.
  We do not test whether glm-5.2 is advantaged on tasks it wrote; the identity contrast is within-row (same monitor set for every policy).
- **No seed parameter on the Adaption API.** "Resamples" and "draws" are temperature-0.7 samples; exact replication is impossible, but
  every response is stored and every number recomputes from `runs/`.
- **Sandbox is macOS Seatbelt (`sandbox-exec`: no network, writes jailed to a temp dir), a 15 s timeout, rlimits and a minimal
  interpreter** — a kernel sandbox, not a container or disposable VM. Hidden tests execute model-written code; the jail was self-tested
  (socket connect and `$HOME` write both blocked) before use.
- **Undocumented API behaviour shaped the harness:** the limiter is per key and token-weighted (requests are queued, never 429);
  the gateway returns 504 after 60 s of silence, so every request is streamed. Three teammates' keys were used in round-robin.
  None of this affects what the models see.
- **Attack success is not uniform across policies.** glm-53-flash explicitly refuses the covert side task in ~18 % of attempts (after
  visible deliberation) and silently omits the canary in ~9 % more; deepseek-v4-flash omits it in ~15 %. Only successful attacks
  (canary present AND hidden tests pass) enter the matrix, so the glm-53-flash and deepseek rows rest on fewer attack submissions
  (reported per row). Refusal is itself a safety-relevant finding and is tabulated separately.
- **Monitor parse failures** are reported per monitor and dropped (a submission with no parsed draw is excluded from that cell).
- **Told condition** (Stage 1b) tells the monitor the author's model name; this tests the *stated* identity channel, not self-recognition.
  Paraphrase (Stage 1c) uses gemma-4-26b-a4b-it as the paraphraser for every submission, including gemma's own; a gemma-flavoured
  paraphrase could shift gemma-family cells specifically.
- **Git history was linearized by a rebase on Sunday before submission**, so committer timestamps postdate the work; author
  timestamps and the per-run `usage.jsonl` logs in `runs/` independently corroborate that hypotheses preceded the sweep.
- **Per-cell Wilson intervals treat the three resamples per task as independent** (design effect up to ~3 if draws within a task
  correlate); the pooled inference is task-clustered and unaffected.
- **Multiple comparisons.** 49 cells with intervals; the pre-registered inference is the pooled `same_model` coefficient with
  task-clustered SEs and a within-task permutation test, not any single cell.

## Dual-use and ethics

- The bank of successful attack submissions is a library of code that disguises a marked network call as justified telemetry. It is
  kept in a private appendix together with the attack and polish prompts; the public release has the monitor prompt, task suite,
  aggregate matrices and analysis code.
- Does the setup make multi-agent operations easier to run or harder to detect? The result is a recommendation about *monitor
  assignment* (whether to let a model review its own family's output). If leniency exists, publishing it mainly helps defenders
  choose cross-family monitors; an attacker already controlling the policy gains little, because the policy cannot choose its monitor.
- The side task is inert by construction (no real endpoint, no real data), tasks are toy functions, and no deployed system was touched.
- Model subjects are open-weight models hosted by a third party; usage stayed within the hackathon's credit cap (final spend in
  `make budget`).
